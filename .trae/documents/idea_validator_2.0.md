# Idea Validator 2.0: 彻底告别废话与套路

## 一、 当前核心问题诊断（为什么觉得“全是废话”）
作为你的联合创始人，我完全同意你的看法。现在的版本确实存在致命缺陷：
1. **用户其实不知道自己要做什么**：用户输入“我想做一个给博主用的剪辑工具”，这太宽泛了。如果 AI 强行基于这句废话去分析，那给出的只能是“废话级的 SWOT 和套路建议”。
2. **缺乏真实数据支撑**：全是大词（“目标人群”、“蓝海”），没有真实的定价、功能点、Reddit 吐槽原话。
3. **结构松散**：报告没有主线逻辑，看完之后不知道该干嘛。

---

## 二、 颠覆性重构：引入“双段式工作流 (Two-Step Workflow)”

我们必须打破“输入一句话 -> 直接出报告”的死板模式。

### 阶段一：AI 灵感榨汁机 (Idea Refinement Chat)
**核心逻辑**：用户往往说不清自己想做什么，甚至不知道该做什么。所以，在生成最终报告前，必须有一个**极其犀利、能够引导用户深挖的“头脑风暴”阶段**。

*   **流程**：
    1.  用户输入初步 Idea（例如：“想做个短视频工具”）。
    2.  系统不会马上出报告，而是进入**“顾问质询模式 (Clarification Chat)”**。
    3.  AI 会连珠炮式地追问 1-3 个致命问题：
        *   “短视频工具太多了。你是想帮小白一键生成，还是帮专业博主做自动字幕？你觉得你比剪映牛逼在哪里？”
    4.  用户在这个过程中可以继续和 AI 聊天、头脑风暴，逐渐把一个“伪需求”打磨成一个“具体的切入点”。
    5.  当用户觉得“这个点子磨得差不多了”，点击 **“🚀 就做这个，给我扒竞品底裤”** 按钮。

### 阶段二：硬核数据大起底 (Hardcore Teardown Report)
**核心逻辑**：基于刚才聊透的最终 Idea，系统去全网抓取真实数据，输出一份**极具攻击性、只有干货的“拆解报告”**。

*   **报告内容（彻底抛弃旧结构）**：
    1.  **竞品扒皮 (Competitor Teardown)**：
        *   不仅有名字和链接，还要列出它们的**核心主打功能**和**推测的定价区间**。
        *   最重要的是：**它们目前做得很烂、用户在骂的点（Opportunity Gap）**。
    2.  **真实痛点挖掘 (Voice of Customer)**：
        *   AI 必须模拟或总结出用户在真实社区（如 Reddit、知乎）里的原话吐槽（例如：“剪映好是好，但我每次加特写镜头都要手动搞半天，太烦了！”）。
    3.  **冷启动实操手册 (First 10 Users Guide)**：
        *   直接告诉用户：你的 MVP 只需要做哪 3 个功能（砍掉所有没用的）。
        *   你去哪个渠道发第一篇帖子（比如去 V2EX 找独立开发者，还是去小红书找博主）。

## 三、 技术改造方案

为了实现这个颠覆性的体验，我们需要做以下改动：

1.  **新建 API `app/api/validator/clarify/route.ts`**：专门负责阶段一的“头脑风暴”流式对话，引导用户细化 Idea。
2.  **重写 API `app/api/validator/analyze/route.ts`**：修改 System Prompt 和返回的 JSON 结构，要求它只输出硬核数据（竞品拆解、真实吐槽、冷启动计划），绝对禁止废话。
3.  **大改前端 `app/validator/page.tsx`**：
    *   移除一开始的大输入框直接生成报告的逻辑。
    *   改成类似 ChatGPT 的交互：先聊天，等点子成熟了，界面右侧或下方再弹出一份极具冲击力的“硬核拆解报告”。

这个方案能彻底解决“用户说不清”和“报告全是废话”的问题。如果你觉得这个方向“对味了”，我就立刻开始改代码！
